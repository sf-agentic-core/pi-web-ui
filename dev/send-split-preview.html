运行中发送区：插队 + 排队 合并为「对半分」按钮

现状：空闲时右侧只有 ↑ 发送 一颗蓝圆；运行中变成 排队（文字 pill）＋ ■ 停止， 而「插队」（回车语义）没有可见入口。目标：运行中把发送位改成 插队、排队收成图标，两者合成一颗对半分的按钮。 下面 4 个方案都是左右／上下各占 50%，可直接对比几何、配色与空输入时的表现。

方案 A — 对半胶囊（同体蓝，细分隔线）

推荐

一颗 78×38 的实心蓝胶囊，中间一条 1px 半透明白线分成两半：左半 = 排队（列表图标，加一层 14% 白底压暗）、右半 = 插队（↑）。停止仍是右侧独立的蓝圆。视觉上是「一颗按钮」，命中区各 39×38。

改动最小：沿用发送按钮的蓝底/阴影/位移悬浮，视觉上与空闲态是同一颗按钮的「变形」。
触屏友好：每半 39×38，都远超 32px 建议命中尺寸；无 hover 也能读懂。
两半同为蓝白，主次偏弱：插队才是主操作，却和排队同样亮。
插队图标同为空闲态的 ↑，语义切换靠位置（左多了一颗排队），新用户需要一次学习。

方案 B — 对半胶囊（左幽灵 / 右实心，2px 断缝）

主次最清晰

胶囊外面套一圈 2px 底色壳，内部左右各 38×34 对半：左半线框幽灵（排队、低饱和、hover 才变紫）、右半实心蓝（插队）。主次一眼分明，同时仍是一颗圆角整体。

插队 = 主按钮，排队是安静的副操作，与「回车插队」的心智一致。
幽灵半段复用现有 .btn 的安静风格，夜间不刺眼。
外壳 + 断缝让按钮比现状更宽一点（≈92px），窄屏（≤560px）更挤。
左半对比度低，可发现性差；触屏没有 hover，排队的可达性靠图标本身。

方案 C — 上下对半的单圆（省横向空间）

窄屏

保持 38×38 圆形不占额外宽度：上半 12px 高的排队（14% 白底＋列表图标），下半 12px 高的插队（↑），中间 1px 分隔线。横向占用与空闲态完全一致。

零额外宽度，手机端 / 左栏拉窄时最稳，永远不换行不挤压 chip。
与空闲态的几何完全一致，切换时右侧工具条不跳动。
每半只有 38×19，触屏极易误点（插队/排队代价相反：误触排队会延迟发送）。
上下分半对图标是种浪费（16px 图形塞进 19px 高），语义也不如左右直观。

方案 D — 悬停才分裂

最低视觉噪音

平时就是原来那颗 38px 蓝圆（↑ 插队，完全复刻空闲态）；鼠标移上去才从左边 180ms 展开「排队」半段，变成 76px 的对半胶囊，移开收回。首次鼠标进入后保持展开（右图 keep 演示常驻展开态）。

运行中与空闲看起来一样，只有功能变了；静止态最干净。
不打断流式界面的安静感，排队是「想找才找」的副操作。
触屏基本不可用（没有 hover，排队发现不了）——必须配 @media (hover: none) 回落成方案 A 的常驻胶囊。
宽度动画会推动工具条左侧 chip，快速掠过时可能闪动。

「排队」用哪个图标

插队固定用 ↑（与空闲态发送一致，不出戏）。排队候选（都取自项目已用的 react-icons/fi）：

无论选哪个，两半都必须带 title（排队：加入队列，AI 回答完全结束后才发送 / 插队：立即插队，本回合立刻响应），并补 i18n key。
placeholder 文案（「…或点『排队』…」）不用动，图标态靠 title 兜底。
不要用 FiSend 做插队：纸飞机与空闲态发送重复，和排队图标放一起难分辨。
不要给两半用同色同图标风格（如都实心蓝）——触屏无 hover，分不清哪半是哪个。

A 同体蓝胶囊78px平权好低（纯 CSS + 一个 wrapper） 最稳的默认选择，先做它。
B 幽灵 / 实心≈92px清晰中（左半偏暗）低 最像「主按钮 + 副按钮」，但更宽。
C 上下对半圆38px平权差（误触）低 只适合作为 ≤560px 的窄屏降级形态。
D 悬停分裂38px → 76px平权差（需回落）中（宽度动画 + hover 媒体查询） 桌面端最安静，触屏必须走 A。
可组合：桌面用 D、触屏用 A（@media (hover: none) 切换），窄屏（≤560px）再降 C —— 共用同一段 React 结构，只换 class。
三个状态（空闲 / 运行未输入 / 运行已输入）都要过一遍 snapshot 与 i18n key（steerTip、queueTip 之类的新 key 需要 zh + en + 8 个语言包）。
运行中未输入时两半都提交不了：建议保留但禁用（尺寸不跳、位置不跳）+ 整颗胶囊变暗，只有停止可用 —— 预览勾选框右侧的行为即是。例外：纯附件（无文字）也能发，那时两半照常可用。
明确不合并停止：停止与插队/排队语义相反，挤进同一颗按钮会误点成中止（或反过来中止失败）。
