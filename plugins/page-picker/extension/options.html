界面语言
默认跟随浏览器语言（中文界面显中文、西班牙文显西班牙文，其它语言一律英文）。 选了具体语言就固定用它 —— 选项页与页面上的拾取浮条同时生效。

pi-web-ui 元素拾取

在开发网页上按扩展图标（或 Alt+Shift+P）开始拾取，选中的元素会整理成上下文注入 pi-web-ui 的输入框， 你补一句说明再发送。
pi-web-ui 服务
只预置了 localhost / 127.0.0.1 的权限。换成局域网 IP、域名或 https 地址（远程部署就是这种）后： 先点「授权该地址」。
更省事的办法：直接在 pi-web-ui 页面上点扩展图标 —— 扩展会认出那个页面， 在页面上问你「要不要把它设为服务地址」，地址和端口都不用手打。
投递是往浏览器里打开的那个 pi-web-ui 页面注入内容的，所以这个地址的页面得开着（可以在另一个标签页/窗口，不必是当前标签）； 页面关着时会退化成「复制 Markdown 到剪贴板」。
检测到 pi-web-ui 页面
AI 操作页面（让模型能读写网页）
授权之后，模型在对话里就能用 browser_page 工具操作那个页面： read（读文本 / 查元素）、click、type、scroll、goto、 wait，以及开关打开后的 eval（执行任意 JS）。
另一端固定是 pi-web-ui 页面本身：模型的动作要从浏览器里那个 pi-web-ui 页面 送进扩展，所以那个标签页得开着（与拾取投递同一个取舍）；这里只需要授权被操作的那个页面。
只对你信任的页面授权：授权后模型能点它、在它里面输入、读它的内容。可以随时收回。
地址不用手打：在目标页面上点一次扩展图标，它就会出现在候选里；或者在开发页的拾取浮条上点 「让 AI 操作本页…」，本页会自动预填好。
页面桥（让两个页面互相读写）
配对之后，这两个页面里的脚本可以互相调用： 对端用 window.__piBridge.on("readOrders", () => …) 注册能力，这边用 await window.__piBridge.call({ op: "readOrders" }) 拿到结果。跨源、跨标签页、跨窗口都行 —— 浏览器里只有扩展能做到这件事。
桥默认关闭：只有下面列出的配对能通，两端的 host 权限由你在这里授权。 被配对的页面里，任何脚本（包括第三方广告/统计脚本）都摸得到 window.__piBridge，所以只对你信任的页面开桥。
地址不用手打：在要配对的两个页面里各点一次扩展图标，它们就会出现在上面两个输入框的 候选下拉里（点一下就填好了）；在开发页的拾取浮条上点「与另一页配对…」还能直接把本页预填好。
例子：在开发页里读线上后台的数据（on("orders", …) 在后台页）， 或者让 A 页控制 B 页（on("highlight", ({id}) => document.querySelector(`#${id}`)?.scrollIntoView())）。 对端页面没打开、或者没注册那个 op 时会得到一句说明原因的错误，而不是「没反应」。
